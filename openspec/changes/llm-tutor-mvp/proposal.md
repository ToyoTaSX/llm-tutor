# Proposal

## Why

В лабораторных (`rag_lab/`) уже собран рабочий RAG-конвейер по лекциям курса «Технологии нейронных сетей»: гибридный поиск BGE-M3 + Qdrant и ответы локальной LLM через llama-server. Но пользоваться им можно только из консоли: один корпус, полная переиндексация, нет пользователей, нет обратной связи. Нужна веб-система, где студент получает подсказку по лекциям и оценивает её, а лектор пополняет базу лекций и видит, насколько ассистент полезен.

## What Changes

- Новое веб-приложение «ИИ-тьютор» с двумя ролями: **студент** и **лектор** (админ).
- Регистрация и вход по логину и паролю. Роль лектора определяется списком логинов в `.env` (`LECTURER_LOGINS`), без паролей в конфигурации.
- Режим «вопрос–ответ» (без многоходового диалога): ответ стримится по токенам и опирается только на фрагменты лекций.
- Панель «Источники» в стиле правой панели LM Studio: найденные фрагменты с названием документа, рангом и полным текстом. Ссылки `[n]` в ответе кликабельны.
- Оценка каждого ответа студентом по шкале 1–5 звёзд.
- Журнал запросов: дата, пользователь, вопрос, ответ, источники, оценка, замеры времени и токенов.
- Интерфейс лектора:
  - загрузка и индексация `.txt`-лекций, удаление и переиндексация;
  - статистика: средняя оценка, распределение оценок, активность, доля ответов «тема не разбиралась», лог последних вопросов с источниками.
- Индексация становится инкрементальной: по документам с `doc_id`, а не пересборкой всей коллекции, как в `rag_lab/ingest.py`.
- Запуск всей системы одной командой `docker compose up`: frontend, backend, llama-server и Qdrant, с GPU.
- Интерфейс в тёмном стиле LM Studio на React.

Вне рамок: форматы кроме `.txt` (PDF, DOCX), многоходовой диалог с контекстом, публичное развёртывание и многопользовательская нагрузка, смена модели из UI.

## Capabilities

### New Capabilities
- `user-auth`: регистрация, вход по логину и паролю, сессии (JWT), определение роли из `LECTURER_LOGINS`, защита эндпоинтов по роли.
- `rag-qa`: приём вопроса, гибридный поиск по проиндексированным лекциям, потоковая генерация ответа, выдача источников, оценка ответа 1–5, история вопросов студента.
- `lecture-documents`: загрузка `.txt`-лекций, нарезка, эмбеддинги, инкрементальная индексация, список, удаление и переиндексация документов, стартовая индексация демо-корпуса.
- `usage-analytics`: журнал вопросов и ответов, агрегированная статистика использования и качества для лектора.
- `deployment`: контейнерная сборка и запуск одной командой, GPU-доступ, конфигурация через `.env`, подключение локальных моделей.

## Impact

- Новый код: `backend/` (FastAPI, SQLAlchemy + SQLite, ядро RAG из `rag_lab/rag_core.py`), `frontend/` (React + Vite + TypeScript + Tailwind), `docker-compose.yml`, `.env.example`.
- Переиспользуется из `rag_lab/`: `encode()` для BGE-M3 dense+sparse, гибридный поиск с RRF, системный промпт, нарезка предложениями с перекрытием. `QdrantClient(path=...)` заменяется на клиент к серверу Qdrant.
- Внешние зависимости:
  - образы `ghcr.io/ggml-org/llama.cpp` (server-cuda) и `qdrant/qdrant`;
  - PyTorch с CUDA 12.8 (`cu128`), FlagEmbedding, qdrant-client, openai.
- Железо: RTX 5060 Ti 16 ГБ (Blackwell, sm_120) под Docker Desktop + WSL2. Нужны образы с поддержкой CUDA 12.8+.
- Модели монтируются с диска: `Qwen2.5-3B-Instruct-Q4_K_M.gguf` и `BAAI/bge-m3`.
- `rag_lab/` остаётся без изменений как справочный материал.
